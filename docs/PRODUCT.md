# Mio 产品企划 · 1.0

## 产品定位

给本地音乐收藏者一个安静、可信的整理工作台。核心价值是让用户知道文件有什么问题、匹配到的内容来自哪里、写入会发生什么，以及如何恢复。不是在线音乐下载器，也不是通过文件后缀给出“真无损”保证的认证器。

## 用户需求到产品闭环

| 最初想法 | 完整产品行为 | 验收标准 |
|---|---|---|
| 上传音乐看频谱、判断真无损 | 本地导入；原采样率多窗口频谱；解释编码、带宽和证据限制 | 可视化来自真实解码；不把 FLAC 后缀当作来源证明；静音不作肯定判断 |
| 自动找到歌词 | 使用现有标签搜索，按歌曲、歌手、时长排序，用户选择具体版本 | 展示候选版本、来源和时长；不自动覆盖错误候选 |
| 日语带罗马音 | 离线转写，保留原文和时间轴，支持人工修订 | 标准原文单独保存；可导出双行 LRC；原文变化后清空失效转写 |
| 缺封面自动补全 | 专辑与歌手查发行版，选择并预览封面 | 已有封面不覆盖；来源可追溯；失败可本地导入 |
| 嵌入音乐文件 | 标准标签写入 + 独立罗马音字段 | 写入不重新编码；副本校验；备份可恢复 |
| 简约优雅的 UI 动画 | 原生窗口、低饱和色、四个任务页、轻微淡入 | 操作有忙碌状态；后台任务不阻塞主线程；不强制花哨动效 |

## 关键取舍

1. 自动查找，人工选择：音乐版本多，错误元数据比缺失元数据更难发现。1.0 不做盲目一键批量覆写。
2. 本地优先：原始音频不上传，不要求注册账号。联网内容只用于用户请求的匹配。
3. 无损判读诚实：显示频谱、规则和不确定性，不销售无法验证的百分比“真无损概率”。
4. 先保证原件：保存比动画优先，出错尽可能不触碰原件，备份长期保留。
5. 格式分层：先保证 FLAC / MP3 / M4A 写入正确，其他格式提供分析与歌词导出。

## 信息架构

左侧工作台保存本次导入的歌曲列表；右侧上部始终显示当前音乐信息及试听；下部四个页签按用户任务排列：音质透视、歌词与罗马音、专辑封面、写入与记录。底部持续显示操作状态。

视觉采用暖灰白底色 `#f5f5f1`、浅鼠尾草侧栏 `#eaece5` 和深绿操作按钮 `#344f3c`。谱图为深绿至暖黄色。圆角卡片提供信息分组，230ms OutCubic 淡入只用于页面过渡。窗口保留标准系统控制和缩放行为。

## 版本边界与后续方向

1.0 实现完整的逐首整理流程、便携发布、测试和文档。它不是经过大规模真实曲库验证的商用长期维护版本，需在不同播放器和真实音乐收藏上继续回归。

后续可按实际反馈推进：全曲分块扫描、用户可调分析阈值、Chromaprint 指纹识别、更多元数据供应商、可暂停任务队列、多选批处理预览、持久草稿、签名安装包、播放器兼容性矩阵和可恢复的多步历史。上述条目是路线图，不属于当前已实现功能。
