# 架构与实现

## 模块

- `mio/ui.py`：Qt 原生窗口、主题、轻量动画、导入、编辑、试听和后台任务编排。
- `mio/core.py`：音频标签读取、FFmpeg 解码、STFT 与启发式判断、罗马音、事务式写入和恢复。
- `mio/providers.py`：MusicBrainz、Cover Art Archive、封面元数据限频与缓存。
- `mio/lyrics.py`：网易云 / 酷狗 / LRCLIB 独立适配器、并行查询、按需正文获取、缓存与故障隔离。
- `tests/`：合成音频端到端测试、异常路径、匹配排序、GUI 草稿与线程验证。
- `scripts/build.ps1`：PyInstaller 目录式打包。`scripts/preview.py`：可重复的界面截图。

## 任务与线程

QThreadPool 使用单个后台工作线程。网络查询、解码、转写、文件写入都在 worker 执行，通过 Qt Signal 回到主线程更新界面。忙碌时禁止改选文件或关闭窗口，防止任务结果错配与写入中断。导入文件夹递归在 worker 完成。没有全局批量自动写入。

## 频谱与结论

保留原始采样率，支持 8–384 kHz。在歌曲 8%、44%、80% 附近开始取最多 12 秒窗口，短曲去重并对齐文件末尾。每段经 FFmpeg 解码为单声道 float32；立体声混合会丢失声道差异，因此该分析不用于声道相位或立体声质量测量。

使用 SciPy STFT（Hann 窗），采样率不超过 96 kHz 使用 4096 点 FFT，否则 8192 点，重叠 50%。每个窗口展示约 260 列以上的有限时间样本；不同窗口用竖虚线分隔，横轴标记各窗口实际开始时间。频谱图最多显示 24 kHz，算法保留完整 Nyquist 频率范围。

平均功率相对最大频带功率下降 60 dB 以内的最高频率被称为“估计有效带宽”；这只是频谱能量阈值，并非严格的滤波器截止频率估计。显示的谱幅度来自 STFT 系数，不能替代校准声学声压级测量。

判断顺序：

1. 抽样峰值低于 `1e-5`：证据不足。
2. MP3 / OGG / OPUS，或非 ALAC 的 M4A：有损编码。
3. 其他格式采样率至少 44.1 kHz，估计带宽位于 12–18 kHz：疑似有损转码。
4. 其他：未见明显转码迹象。

规则没有使用机器学习分类器，也没有经过标注数据集校准，不输出误导性的“准确率”。高频不足可能来自音乐类型、母带、录音设备、低通处理或转码。单声道混合、抽样与能量阈值还会引入遗漏。JSON 报告保留平均频谱与解释，便于审查。

## 在线来源

v1.1.0 的自动模式使用三个独立后台请求并行搜索：网易云 `/api/search/get`、酷狗 `/search` 歌词搜索、LRCLIB `/api/search`。网易云与酷狗各保留最多八个候选，LRCLIB 保留评分最高的十二个。用户可以只查询其中一个来源；某源报错不会使其他来源失败，结果逐源回到主线程，展示明确状态。全部失败或无结果也不清空编辑区。

候选得分使用 50% 曲名 + 25% 歌手 + 20% 时长 + 5% 专辑相似程度。缺失时长/专辑按中性分处理。曲名做 Unicode NFKC、空白和常见扩展名清理；带歌手查询无结果时退回只查曲名。得分不是正确率，保留各源不同版本供用户选择，不自动覆写。

选择候选后只获取该首正文：网易云 `/api/song/lyric` 的 `lrc` / `tlyric` / `romalrc`；酷狗 `/download?fmt=lrc` 的 Base64 UTF-8 文本；LRCLIB 使用搜索结果中的同步或普通歌词。只处理公开文本接口，不下载音频，不需要登录或破解逐字加密内容。QQ 接口本次实测返回错误，因此未列为可用来源。

请求连接/读取超时为 3.5 / 6 秒，单次 JSON 响应最多 2 MB；503 不在同一个失败来源上反复等待。搜索缓存一天、正文缓存七天，网络故障时可以回退三十天内旧缓存并标记。可勾选强制联网跳过新鲜缓存；该选项仍允许在网络失败时使用标记过的历史缓存。缓存使用独立目录 `cache/lyrics-v2`，临时文件原子替换，不读取旧版格式。HTTP 与应用错误不会写入新缓存。

译文和在线罗马音按 LRC 时间戳对齐，允许 20ms 的舍入差异，保留主歌词顺序，避免简单拼接导致整段错位。没有在线罗马音时仍可离线生成。

封面链路保持 MusicBrainz release 搜索 + Cover Art Archive `release/{mbid}/front-500`。封面元数据请求间隔至少 1.1 秒，429 / 5xx 最多三次尝试，JSON 缓存七天。歌词与封面不再共享一个串行请求锁。

## 标签映射

| 内容 | FLAC | MP3 | M4A |
|---|---|---|---|
| 歌词原文 | Vorbis `lyrics` | ID3 `USLT`（UTF-8） | `©lyr` |
| 原文＋罗马音预览 | `MIO_ROMAJI` | `TXXX:MIO_ROMAJI` | `----:com.mio:ROMAJI` UTF-8 |
| 封面 | FLAC PICTURE type 3 | APIC type 3 | `covr` JPEG |

图片先解码校验并转 RGB JPEG，最长边 1600 px，质量 92。输入上限 12 MB。只补全缺失封面，保持已有封面和其他基础标签。罗马音通过 pykakasi 的 Hepburn 输出生成，LRC 时间戳复制给第二行；无需网络。不对 LRC 元信息行做日语推断。

## 写入事务与恢复

1. 计算原件 SHA-256，校验待写入图片。
2. 在原文件同目录创建临时副本，Mutagen 修改副本标签。
3. 重新读取副本，验证时长、歌词与封面存在。
4. 检查原件哈希未变化，保存完整原文件到 `.mio/backups/<原名>.<哈希前16位>.bak`，校验备份哈希。
5. 使用同文件系统 `os.replace` 替换原件，再记录哈希与来源。
6. 会话撤销先校验当前文件仍为写入后的哈希，且备份哈希有效，再通过临时副本原子恢复。

备份不覆盖既有同哈希备份；备份损坏、外部修改、权限不足等会中止。日志失败会报告已写入与备份状态。操作系统崩溃、磁盘硬件错误及文件系统不提供强原子性时无法给出绝对保证；备份应配合用户自己的存储备份策略。

运行时不会为每次写入全量解码对比音频（开销过大）；音频不变由标签库直接修改元数据的工作方式保障，并由合成音频回归测试验证。测试覆盖 FLAC / MP3 / ALAC M4A / AAC M4A 的解码样本逐点一致与恢复哈希，不代表所有损坏或特殊容器都已覆盖。
